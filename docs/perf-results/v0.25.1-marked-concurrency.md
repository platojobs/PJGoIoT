# v0.25.1：两个客户端并发操作同一设备的 `markedAt` 验证

> 目标：在**真实 HTTP 服务 + 真实 PostgreSQL**上验证三端（Android v0.32.4 / iOS v0.30.0）
> 按契约 0.20.0 同时操作同一 `user_device` 时的行为，不需要真机。
> 复跑脚本：[`scripts/verify-marked-concurrency.sh`](../scripts/verify-marked-concurrency.sh)
> （运行结束时直接打印同样的断言表与结论）。本页记录结论、断言与边界。

连续 3 次运行均 `全部通过`。并发合并后的新增条目数观测到 **1** 和 **2** 两种：

- **1 条**：微秒客户端先拿到用户级写锁 → 毫秒客户端全部 `conflict(server_newer)`；
- **2 条**：毫秒客户端先写入（1 条）→ 微秒客户端随后严格更新（1 条）；此后均为 `unchanged`/`conflict`。
  这是两个**不同**操作（`markedAt` 与 `updatedAt` 都不同），不是重复条目；同一操作重复上报由
  「无同一操作重复条目 = 0」与回放用例单独断言。

## 3. 关键结论

1. **最终值由 LWW 决定，与到达顺序无关**：微秒时间戳的 `updatedAt` 更新，最终落库始终为
   `...123456Z`；毫秒值最多只落库一次。
2. **不会出现「同一操作」重复条目**：对 `(payload->>'markedAt', payload->>'updatedAt')`
   分组计数，无任何组大于 1。用户级 `pg_advisory_xact_lock` 使同用户 push 串行化，
   后到请求能读到前一次已提交的记录。
3. **缺省 ≠ 取消**：`markedAt` 缺省时即使 `updatedAt` 更新，也只更新其他字段，`marked_at`
   保持原值；显式 `null` 才清空。取消后再来缺省，仍保持 NULL。
4. **旧时间戳不能复活标记**：先 `null` 清除，再用更旧的 `updatedAt` 标记 → `conflict(server_newer)`，
   不写库、不新增 `change_log`。
5. **幂等回放稳定**：把服务端返回的 `markedAt` 与原 `updatedAt` 原样回传两次，均为 `unchanged`，
   `change_log` 条目数不变。
6. **游标推进不受影响**：10 次并发写入 + null/缺省 + 回放后，用 `limit=10` 拉取
   `/sync/changes`，seq 严格递增、无停滞；HTTP 生成的 `scene` 与直接插入的未知
   `legacy_unknown` 都被正常越过，最后空页游标不倒退。

**契约结论**：服务端行为与契约 0.20.0 一致，未发现需要修复的偏差；因此**不改契约、不新增迁移**，
仅按发布流程把服务版本递增到 `v0.25.1`（本页与脚本为验证性改动，无产品行为变化）。

## 4. 哪些是 HTTP 层验证，哪些仍需真机

**本页已验证（HTTP + 真实 PG）**

- 两个客户端不同 `id`、同一 `(platform, externalId)` 的并发 push 与 LWW 结果；
- `markedAt` 三态（缺省 / null / 时间戳）在真实 JSON 绑定、校验、落库、`change_log` payload 中的表现；
- 微秒截断后同一时间戳的 `unchanged` 判定与重复条目抑制；
- `/sync/changes` 的 seq 推进、`nextCursor`、空页终止与未知 entity 越过；
- 落库值、`change_log` 条目数等数据库事实（直接查询 `user_devices` / `change_log`）。

**仍只能靠真机（未验证）**

- Android/iOS 客户端并发调度、重试与网络切换（弱网、离线补传）导致的真实交错顺序；
- 客户端本地库（SQLite/Realm/CoreData）与服务端 LWW 的合并、冲突提示与 UI 表现；
- 设备时钟漂移（超过 2 分钟 `MaxClockSkew` 的兜底路径）在真实设备上的发生频率；
- 多账号/多设备（>2 客户端）、跨平台（Android 与 iOS 同时操作）以及长时间高频标记的吞吐；
- 推送通知、后台任务、进程被杀后重放等客户端生命周期行为。

## 5. 未覆盖

- 未知 entity 由 `psql` 直接插入 `change_log` 模拟（HTTP 没有对应的写入入口），只验证读游标不因此停滞；
- 并发只用了 2 个客户端、10 轮；更高并发下的锁等待与 p95 未测；
- 真实设备时钟与服务端时区/夏令时差异未覆盖。
